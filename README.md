# 泰国站库存与补货管理 · GitHub Pages 版

中文库存工具，可直接在浏览器中导入 XLSX、计算库存风险与补货、维护采购及分批出货。

公开网站地址：部署完成后使用 https://xiba233.github.io/thai-inventory/ 。

## 第一次使用

1. 打开网站，等待浏览器运行组件加载，首次约 13 MB。
2. 有旧系统完整迁移备份：点击 **备份与迁移**，选择自己的 `.json` 完整备份，核对并恢复。
3. 没有备份：点击 **数据导入**，选择标准 XLSX，解析预览，再正式导入。
4. 查看运营总览、风险与补货建议。未确认的供应链周期会明确显示暂定假设。
5. 完成当天操作后，点击 **备份与迁移 → 下载完整备份**。

操作说明页面提供分步骤指南。库存 Excel 仅更新库存快照，采购、清仓及设置继续保存。

## 数据在哪里

- 库存、参数、导入历史、采购、出货、在途、清仓配置保存在当前浏览器的 IndexedDB 中。
- 不向 GitHub 上传 Excel、备份或业务数据；公开仓库只包含应用与运行组件。
- 关闭网页再打开会读回数据。无痕浏览、清除网站数据或换浏览器会影响本地存储，请定期备份。
- 不同设备不自动同步。新设备打开相同网址后，恢复主设备导出的完整备份。
- 完整备份是数据 JSON，带完整性校验。恢复替换当前浏览器的数据，不执行备份中的 SQL 或代码。
- 表格导出的 CSV 仅用于查看和采购计划，不能代替完整备份。
- 多人使用时约定一个人维护主备份。此版本没有多人共同数据库或冲突合并。
- 同一浏览器多个标签页通过 Web Locks 串行操作，并用存储版本校验防止覆盖；建议在一个标签页维护。

## 保留的业务功能

- 固定表头 Excel 预览、校验、重复导入记录与失败报告；库存快照覆盖而非累加。
- 7/15/30 天加权销售速度、库存覆盖天数、P0-P3 风险与可解释的补货计算。
- 工厂、国内、跨境天数与安全库存；SKU 独立覆盖及批量维护。
- 采购三字段录入、按 SKU 自动关联、分批出货转入在途、误录撤销、删除与恢复采购。
- 在途 ETA、快照归属核对、删除明细与避免重复累计。
- 人工清仓标记、精确映射审查、清仓完成持续排除及恢复。
- 中文筛选、搜索、排序、CSV 导出与操作说明。

## 计算与运行结构

- `index.html / app.js / help.js / style.css`：中文业务页面。
- `storage.js`：串行调用、跨标签页锁。
- `worker.js`：在后台浏览器线程加载 Python，运行服务并将 SQLite 文件原子保存至 IndexedDB。保存失败不报告成功，恢复上次持久化数据。
- `browser_bridge.py`：原服务接口适配与完整备份/恢复校验。
- `business.zip`：完整 Python 业务源码（`inventory`）及 openpyxl、et_xmlfile。解压后可审查计算、导入、采购与数据库层。
- `pyodide* / python_stdlib.zip / *.whl`：固定版本 Pyodide 0.28.3、SQLite 和时区运行组件。全部由本站提供，不依赖第三方 CDN 运行。
- `运行组件来源.json / THIRD_PARTY_NOTICES.md`：组件来源与许可证说明。
- `.nojekyll`：按原样发布静态文件。

SQLite 结构和业务服务与本机版本一致。工厂生产、物流时间及预计入库日期仍需维护真实值；不会生成虚假每日销量、采购单号或 ETA，也没有 ERP 实时同步。

## GitHub Pages 发布

将本目录顶层文件放在公开仓库 `main` 分支根目录，保留所有运行组件。进入 **Settings → Pages → Deploy from a branch → main → / (root) → Save**。

仅上传公开程序文件。不要上传真实 `.xlsx`、`.db`、业务备份 `.json` 或私密迁移目录。

现代 Chrome、Edge 等支持 WebAssembly、Web Workers、IndexedDB 的浏览器可用。网络较慢时首次加载需稍等；本地双击 HTML 的 `file://` 模式不支持，请通过 Pages 或静态 HTTP 服务访问。
